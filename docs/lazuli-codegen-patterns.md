# Lazuli Codegen Patterns

Last updated: 2026-05-12. Captures the conventions established
across cells E1-G7 + parallel batches 1-3 (20 Codex agents).

## 1. Emitter file layout

Each kind lives in `crates/lazuli_codegen_go/src/emitter/<kind>.rs`
with an entry function:

```rust
pub fn emit_<kind>_file(
    source_label: &str,
    feature: &Feature,
    module_name: &str,
    cross_index: &CrossFeatureIndex<'_>,
) -> Option<String>
```

Returns `None` when the feature has zero declarations of that kind.
Generated Go uses one file per feature/kind:
`dist/go/<feature>/<kind>.gen.go`. Module-level files (`go.mod`,
`main.go`, `lazuli_app.gen.go`) are owned by `emitter/module.rs`.

## 2. Type resolution

All type refs go through `types::go_type_for(&type_ref, &TypeCtx)`.
`TypeCtx` carries `current_feature`, `module_name`, and `cross_index`.

Cross-feature refs resolve via `CrossFeatureIndex` (`Resource.name`,
`Record.name`, and `EnumDecl.name` per feature). The emitted Go type is
`<owner>.<Name>`, and the emitter registers a `<module>/<owner>` import.

Closed type catalogs stay centralized:

- `@cap.Hashed`, `@cap.Encrypted`, `@cap.Token`, and `@cap.File` map from
  typed `CapabilityRef` variants.
- `@semantic.*` maps from the closed semantic table. `@semantic.GeoPoint`
  maps to `postgis.Point` and the chosen PostGIS Go binding import.
- Unknown capability or semantic refs are diagnostics, not best-effort
  strings.

## 3. Casing

`emitter::casing::pascal_case` and `lower_camel` are the canonical
helpers. They handle snake case, kebab case, PascalCase, and word
transitions.

Leading acronyms lowercase entirely for lower camel names:
`id_lookup` -> `idLookup`.

## 4. Determinism

- Always sort iteration: `BTreeMap`, `BTreeSet`, or `sort_by_key`.
- `ImportSet` de-dups via `BTreeSet`.
- Imports classify into three buckets: standard library,
  `lazuli.dev/runtime/lazuli`, and third-party.
- Import blocks use three blank-line-separated groups.
- Output must be byte-identical across runs.
- Codegen does not invoke `gofmt`; it emits `gofmt`-equivalent text and
  smoke tests check `gofmt -l`.

## 5. Lazuli Go lib gaps

When a referenced runtime type does not exist:

- Emit `// TODO(runtime): <description>` in the generated value literal.
- Never modify `runtime/go/lazuli/**` from codegen.
- Let the runtime team add the type in a separate cell, usually a
  `Section 4.X` backfill cell from the proposal.

This keeps the emitter thin: Lazuli Go is the hand-written wire over
mature Go libraries; codegen emits typed contracts and calls, not
runtime implementations.

## 6. Cell taxonomy

- **E** - emitter scaffold / per-kind (`E1` scaffold, `E2-E4` and
  `G1-G7` kinds).
- **I** - integration (`I1` CLI verb, `I2` root, `I3` smoke,
  `I4` check mode).
- **G** - group/kind (`G1` Auth, `G2` jobs + webhooks + notifications,
  and related grouped emitters).
- **Section 4.X** - Lazuli Go lib backfill, per proposal Section 4.
- **R** - re-emit / refactor (`R1` cross-feature fix,
  `R2` G6 emit drop TODOs).
- **D** - doctor diagnostic.
- **L** - runtime lib helper.

- One isolated file per agent, with zero expected merge conflict.
- Wire-up in `mod.rs` and `module.rs` is the orchestrator's job after

- Codex plans via ChatGPT; Claude orchestrates dispatch, merge, and
  final verification.

## 8. Boundary discipline

The emitter consumes typed `lazuli_ir::Module` data directly. Do not add
text-pattern walkers, `serde_json::Value`, or dynamic map plumbing to
recover shape that already exists in IR.

The emitter must not:

- Implement algorithms such as argon2, HMAC, JWT signing, retries, or
  queue dispatch.
- Touch `runtime/go/lazuli/**`.
- Generate imports under retired nested plugin namespaces.
- Emit type-erased `map[string]any` for typed surfaces.
- Overwrite user-authored extension files, SQL files, or translation
  catalogs.

The emitter must:

- Emit `// Code generated by lazuli; DO NOT EDIT.` on generated Go files.
- Resolve refs through `emitter/refs.rs`.
- Surface unresolved refs through closed diagnostics.
- Keep generated files readable enough for direct review.

## 9. Typed IR assumptions

Rows 60-69 of `docs/next-checklist.md` establish the input contract:

- Commands, resources, queries, records, APIs, policies, enums, and
  external calls are typed IR; no Tier 4 text-pattern walker remains.
- Auth is typed through identity, password, sessions, MFA, and OAuth.
- Storage uses typed `@cap.File` lowering with visibility, signed TTL,
  size, and MIME metadata.
- Jobs, webhooks, notifications, and event groups are typed IR with
  runtime contract stubs present.
- Command Tier 4 fields (`timeout`, `retry`, `idempotency`,
  `external_calls`) mirror the job-side shape and should not be
  re-parsed from text.

Codegen should lean on those typed fields even when runtime support is
still yellow.

## 10. Reference resolution

`emitter/refs.rs` owns the closed resolver for `@runtime/`, `@plugin/`,
`@adapter.`, `@fn.`, `@semantic.`, and `@cap.` references.

Rules:

- Core runtime refs import `lazuli.dev/runtime/lazuli/...`.
- Private plugin refs import separate plugin modules such as
  `github.com/lazuli-lang/lazuli-plugin-<name>`.
- Codegen never emits `@plugin/<product>/<name>`; that namespace form is
  retired.
- Adapter and function refs may remain string literals only when the
  resolver explicitly classifies them that way.
- `--check` mode reports unresolved refs with stable `CODEGEN-GO-*`
  diagnostic codes.

## 11. Readiness shorthand

- **Green** - IR exists, runtime contract exists, and generated Go is
  expected to build without TODOs.
- **Yellow** - IR exists, but runtime contract shape, adapter wire, or
  smoke coverage is incomplete. Emit TODOs rather than editing runtime.
- **Red** - language or IR shape is incomplete; do not fake it in
  codegen.

Known green or near-green slices include resources, records, commands
create/update/delete, query list/lookup, auth declaration, storage file
contracts, and job contracts. Expanded webhook, notification digest or
throttle fields, API contracts, command Tier 4 slots, and SQL query
smoke coverage should be checked against the current runtime state before
removing TODOs.

## 12. Verification gates

Minimum checks for emitter changes:

- `cargo test -p lazuli_codegen_go`
- Two consecutive emits produce byte-identical output.
- `gofmt -l dist/go/` returns empty in smoke output.
- With smoke enabled: `go mod tidy`, `go build ./...`, and `go vet ./...`
  pass for the generated green slice.

When a kind emits TODOs for runtime gaps, tests should assert the TODO is
intentional and easy to remove after the matching runtime backfill lands.
