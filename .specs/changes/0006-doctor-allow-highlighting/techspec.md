# TechSpec — doctor:allow highlighting

## Approach
Grammar-only. Replace the flat `comments` repository rule in `editors/vscode/syntaxes/lazuli.tmLanguage.json` with an ordered `patterns` list whose first entry scopes the `# doctor:allow <CODE> — reason "<text>"` directive and whose last entry is the existing catch-all `#.*$`. No Rust, no IR, no `#kw-*` regeneration. Because every block rule already `include`s `#comments`, editing this one rule lights up suppressions everywhere. Snapshot-test the result with a fixture line + regenerated `.snap`.

## Contracts
**Replacement `comments` rule (shape — the agent finalizes exact regex against the snapshot):**
```json
"comments": {
  "patterns": [
    {
      "name": "comment.line.number-sign.directive.lazuli",
      "match": "(#)\\s*(doctor:allow)\\s+(\\S+)(?:\\s+(—|--)\\s*(reason)\\b)?",
      "captures": {
        "1": { "name": "punctuation.definition.comment.lazuli" },
        "2": { "name": "keyword.control.directive.lazuli" },
        "3": { "name": "entity.name.tag.lazuli" },
        "5": { "name": "keyword.control.directive.reason.lazuli" }
      }
    },
    { "name": "comment.line.number-sign.lazuli", "match": "#.*$" }
  ]
}
```
- The quoted reason text after `reason` is scoped by `#strings` (already the project's string scope). If the chosen form is `begin`/`end`, `include` `#strings` in its inner `patterns`, mirroring `scope-block` (~lines 815–821). If a single-line `match` is used, the trailing `"..."` is highlighted by the top-level/enclosing `#strings` include that already runs on the line — verify against the snapshot and switch to `begin`/`end` if the string is swallowed by the comment scope.
- **Ordering invariant:** the `doctor:allow` pattern MUST come before the `#.*$` catch-all. TextMate first-match-wins; reversing the order makes the catch-all eat the whole line and the directive never highlights.
- **Plain comments unchanged:** any `#` line that is not a `doctor:allow` directive still matches `#.*$` → `comment.line.number-sign.lazuli`.
- **Em-dash + ASCII fallback:** pilots use `—` (em dash); accept `--` too so an ASCII-typed allow still colors its `reason`.
- **Scope names** follow existing conventions: `keyword.control.*` for the directive/reason keywords (cf. `keyword.control.section.lazuli`, `keyword.control.statement.lazuli` already in the file); `entity.name.tag.lazuli` for the diagnostic code; `punctuation.definition.comment.lazuli` for `#`.

## Risks & rollback
- The single-line `match` lets `#strings` mis-scope or the comment scope swallows the quoted reason → mitigation: switch the directive pattern to `begin`/`end` with an inner `#strings` include exactly like `scope-block`; the snapshot makes the failure visible before commit.
- Over-greedy `\\S+` for `<CODE>` captures the em-dash when no reason follows → mitigation: anchor the optional `(—|--)` group and verify the bare-allow fixture in the snapshot.
- A future hand-edit reorders the patterns and the catch-all eats the directive → mitigation: the `directive_with_reason_scoped` snapshot test fails loudly; the ADR records the ordering invariant.

**Rollback:** `git revert` the commit — the change is one repository rule + a fixture + a snapshot; nothing downstream depends on the new scopes at runtime.
