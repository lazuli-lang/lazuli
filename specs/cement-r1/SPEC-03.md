# SPEC-03 — Resolve the silent scalar aliases — reject Id/String/Bool/Int/Float/Json-lowercase with a canonical-suggesting diagnostic + autocorrect, end the silence

**Breaking:** True | **Est. commits:** 6 | **Depends on:** none | **Parallel with:** SPEC-02

## Problem
The analyzer's scalar lowering silently maps six off-catalog spellings to canonical builtins with no lint, no diagnostic, no fmt normalization. `crates/lazuli_analyzer/src/types.rs:160-177` match arms: `"ID" | "Id"` → Id, `"Text" | "String"` → Text, `"Boolean" | "Bool"` → Boolean, `"Integer" | "Int"` → Integer, `"Decimal" | "Float"` → Decimal, `"JSON" | "Json"` → Json. A repo-wide grep confirms zero enforcement: `rg "SCALAR-ALIAS|ScalarAlias|scalar_alias"` returns 0 matches across 2320 files. This directly contradicts three canonical surfaces that declare a CLOSED scalar catalog: (1) the IR enum doc `crates/lazuli_ir/src/nodes/resource/type_ref.rs:55-71` ("Closed catalog of language-level builtin and semantic types") enumerates only `Id/Text/Boolean/Integer/Decimal/Date/DateTime/Json`; (2) the grammar EBNF `docs/grammar.lzi.md:274-275` declares `scalar_type = "ID" | "Text" | "Boolean" | "Integer" | "Decimal" | "Date" | "DateTime" | "JSON"` with NO aliases; (3) `docs/grammar.lzi.md:37` ("The closed scalar/built-in type catalog (`ID`, `Text`, `Boolean`, ...)"). It also violates CLAUDE.md inviolable rule 7 ("Magic discovery requires visibility ... No silent runtime behavior") and the "many faces" rule: the aliases are silently advertised by two LSP code paths — `crates/lazuli_lsp/src/completion/owner_axis.rs:124` offers `"ID" | "Id"` as completions, and the tmLanguage scalar regex `editors/vscode/syntaxes/lazuli.tmLanguage.json:2829` highlights `String|Bool|Int|Float|Numeric` as valid types — so an author/LLM is positively steered toward the off-catalog spelling, then it lowers silently, maximizing output entropy (two spellings per intent ⇒ more retries). Aggravating: the alias set is INCONSISTENT (Date/DateTime have no alias; the analyzer also accepts `Numeric` nowhere yet tmLanguage highlights it; `Email` is hard-coded at types.rs:178 outside both the alias list and the `@semantic.` path), so even the silent behavior is non-uniform. No deliberate rationale exists: `docs/design-decisions.md` (542 lines) has no scalar-alias entry; the `previously alias`/`migrated` rows at design-decisions.md:525 concern resource/field RENAME migration, not type spellings. Scalars are recognized in the ANALYZER, not the parser, so they are NOT in the keyword registry — `crates/lazuli_keywords/tests/proven_complete.rs` scans only `crates/lazuli_syntax/src/**`, so this silent surface has escaped every existing parity gate.

## End state
The canonical scalar catalog is exactly {ID, Text, Boolean, Integer, Decimal, Date, DateTime, JSON} (uppercase-canonical; JSON all-caps). The six aliases (Id, String, Bool, Int, Float, lowercase Json) are REJECTED at analyze time with a hard diagnostic that names the canonical spelling, AND auto-corrected by two existing autocorrect surfaces — no new `lazuli fmt` is invented (none exists today; building a round-trip-safe formatter for six aliases would violate the founding principle). Decision = OWNER-chosen variant of task option (a)+(b) fused: the language REJECTS (not silently normalizes), but every rejection ships an automated fix so the doctrine is "reject + autocorrect, never silently tolerate." Concretely: (1) `crates/lazuli_analyzer/src/types.rs` no longer has alias match arms — an off-catalog spelling that is a known alias lowers to the canonical builtin BUT records a `ScalarAlias` analyzer diagnostic carrying `{found, canonical}`; a truly-unknown name still falls through to `UserDefined` unchanged. (2) `lazuli check`/LSP surface diagnostic `SCALAR-ALIAS-001` (ERROR severity in strict/production, WARN in prototype, mirroring VOCAB-GRAMMAR-FORM-001's profile) reading "scalar `Int` is not canonical — use `Integer`". (3) `lazuli fix SCALAR-ALIAS-001` (via `lazuli_fix`) and a `migrations/recipes/<from>-to-<to>/NN-scalar-alias-canonicalize` regex recipe both rewrite the six spellings in place. (4) The doctor rule `SCALAR-ALIAS-001` (new `crates/lazuli_doctor/src/vocab/vocab_scalar_alias_001.rs`) fires on the deprecated spelling across `.lzi`/`.lzx`, iron-hand-eligible. (5) LSP completion (`owner_axis.rs:124`) drops `"Id"`; LSP typo/hover maps each alias→canonical as a known-deprecation hover. (6) tmLanguage scalar regex (tmLanguage.json:2829) drops `String|Bool|Int|Float|Numeric` from the canonical-type highlight group (these instead match a `deprecated-type` scope so they render visibly different). (7) Grammar/quickref unchanged in the canonical EBNF (already alias-free) but gain an explicit "rejected aliases" note so the closed catalog is self-documenting. After this lands, exactly one spelling per scalar intent reaches codegen; `lazuli inspect`/`generate --check` on any aliased source emits the canonicalized IR with the diagnostic, never a silent pass.

## Justification (token / entropy)
"LLM-first token/entropy justification. PEAKEDNESS (the dominant lever on attempts): today every scalar intent has TWO blessed spellings and the language positively advertises both — LSP completion offers `Id` (owner_axis.rs:124) and tmLanguage highlights `String|Bool|Int|Float` as valid types (tmLanguage.json:2829) — while the analyzer accepts both silently. That is the textbook entropy-inflating shape: a model sampling field types splits probability mass across {Integer, Int}, {Text, String}, {Boolean, Bool}, {Decimal, Float}, {ID, Id}, {JSON, Json}, and because BOTH lower silently, the wrong-for-canon choice is never corrected — it propagates into committed source, fixtures, and the model's own few-shot context, compounding drift. Collapsing to one canonical spelling per intent and REJECTING the alias with a diagnostic that names the canonical drives output entropy toward a delta function: the model that emits `Int` gets an immediate, mechanical correction ('use Integer'), so the expected-attempts term falls. TOKENS-PER-ATTEMPT: the canonical set is already the tokenizer-cheap surface — bare PascalCase English words (`Integer`, `Boolean`, `Decimal`) under cl100k/o200k, no `@sigil`. The aliases are not cheaper (Int vs Integer saves ~1 token but at the cost of a whole extra spelling the model must disambiguate), so removing them costs nothing per-attempt and slashes attempts. EXPECTED TOKENS TO CORRECT OUTPUT = tokens/attempt x attempts strictly decreases. Crucially, the fix preserves the cheap surface (no new sigils, no type-annotation ceremony) while killing the entropy source. The OWNER 'reject + autocorrect, no fmt' decision is itself entropy-minimizing for the maintainer: it reuses the two existing autocorrect surfaces (migrate dsl, lazuli fix) rather than inventing a formatter, honoring the founding 'wire, not reimplementation' principle — a brand-new round-trip-safe source printer for six aliases would be exactly the 200-800-LOC homegrown-logic anti-pattern CLAUDE.md forbids."
