# SPEC-07 — Policy-syntax coherence: uniform reference-or-inline across all callables + kill the CRUD/effect collision (keep @policy as documented reference-namespace)

**Breaking:** True | **Est. commits:** 9 | **Depends on:** SPEC-04 | **Parallel with:** none

## Problem
Lazuli's ~6 policy-bearing forms carry three incoherences that inflate output entropy for an LLM author. (1) ASYMMETRY: the LSP namespace check at `crates/lazuli_lsp/src/diagnostics/policy/namespace.rs:79-90` warns ONLY when `current_top == Some("command" | "workflow")` and the ref is not `@policy.*` — so commands/workflows MUST reference `@policy.*`, while jobs, webhooks, escape_routes, and `policy_for` defaults MAY inline a direct atom. `docs/invariants.md:319-321` admits this is hand-wavy ("may use direct atoms where appropriate"). The divergence is already in canon: `examples/extension-points.lzi:33` and `examples/full-capsule/full-capsule.lzi:631,1013` write `policy @role.admin` inline on `escape_route`, while every command writes `policy @policy.create` (`examples/crm.lzi:107`). An LLM has no single rule for `policy <X>` across callables — it must recall a per-construct table, the high-entropy surface that drives retries. (2) CRUD/EFFECT COLLISION: effect verbs are plural `creates`/`updates`/`deletes` (`crates/lazuli_keywords/src/registry.rs:1981-1996`), conventional policy-category names are singular `create`/`update`/`delete`/`read` (`examples/crm.lzi:90-93`; parser fixture `crates/lazuli_syntax/src/parser/lzi/policy/mod.rs:412` uses `create:`). `docs/invariants.md:322-325` openly states the `@policy.*` prefix exists to keep `policy create` from reading as a write effect — so part of the sigil's job is patching a self-inflicted near-collision. (3) SIGIL-STRADDLE: `@policy.<name>` is a NAMED REFERENCE to a user category, yet shares the `@` sigil with the CATALOG ATOMS `@role`/`@scope`/`@actor`, all registered identically as `decorator(...)` at `crates/lazuli_keywords/src/registry.rs:3204-3207` and grouped on one axis row at `docs/design-decisions.md:146`. Same `@`-overload SPEC-04 resolves for types/references.

## End state
A single coherent model, decided as OWNER. (A) UNIFORM reference-or-inline across ALL policy-bearing callables: `policy <expr>` accepts the same grammar everywhere — `@policy.<category>`, a namespaced catalog atom (`@role.*`/`@scope.*`/`@actor.*`), or a structured policy expression. The command/workflow-only `@policy.*` requirement at `namespace.rs:79-90` is DELETED; one rule replaces the per-construct table. (B) Consistent with SPEC-04's `@=named-ref, bare=catalog/type` doctrine, `@policy.<name>` is RETAINED as the documented reference-namespace for feature-local categories (the `@` legitimately means "named reference"); `@role`/`@scope`/`@actor` are reclassified in the keyword registry from generic `decorator` to a distinct catalog-atom kind so the sigil-straddle is named/enforced (the identity-authorization axis at design-decisions.md:146 is preserved; only the kind distinction is made explicit, surfacing in hover + reference). (C) The CRUD/effect collision is killed at the source rather than patched by sigil: a doctor rule forbids a `policies` category from shadowing an effect verb (no category spelled `creates`/`updates`/`deletes`/`reads` nor the bare-verb `create`/`update`/`delete`/`read`). Canon migrates CRUD-named categories to semantic names, so `@policy.` earns its keep purely as the SPEC-04 reference-namespace marker, not a disambiguation hack. Net: one canonical form per intent (peakedness up → fewer attempts), and the sigil's justification becomes single-purpose and documented.

## Doctor rules
- `POLICY-CATEGORY-SHADOWS-EFFECT-001` (error (iron-hand + production); warning (strict) during the migration window) — A `policies` category name must NOT shadow a command effect verb. Rejects `creates`/`updates`/`deletes`/`reads` and the bare-singular effect spellings `create`/`update`/`delete`/`read` (which read as effect intent at a `policy <X>` site). Kills the CRUD/effect collision at source so @policy. no longer functions as a collision-patch. Module header carries severity + trigger cue 'fires when a policies category is named after a CRUD/effect verb'.
- `POLICY-REF-UNIFORM-001` (warning (strict); error (iron-hand + production)) — Replaces the command/workflow-only check deleted from namespace.rs:79-90. Uniform across ALL policy-bearing callables (command, workflow, query, api, job, webhook, escape_route, lifecycle transition, view guard, route_guard, policy_for): a `policy <X>` reference is well-formed iff X is (a) `@policy.<category>` resolving to a feature-local category, (b) a namespaced atom `@role.*`/`@scope.*`/`@actor.*`, or (c) a structured policy expression. Bare unnamespaced refs warn with one fix-it everywhere. Trigger cue 'warns when a policy reference is neither a resolvable @policy.<category> nor a namespaced atom'.
- `POLICY-CATEGORY-UNRESOLVED-001` (warning (strict); error (production)) — An `@policy.<name>` reference must resolve to a declared feature-local (or feature-qualified) category. Folds in the existing namespace.rs:92-101 'should resolve to a feature-local policy category' check, now applied uniformly at every callable site rather than only where current_top permitted it.
