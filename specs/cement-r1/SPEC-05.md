# SPEC-05 — == for equality — split the comparison operator out of =’s assignment/binding/storage triple role in the closed predicate language

**Breaking:** True | **Est. commits:** 9 | **Depends on:** SPEC-04 | **Parallel with:** none

## Problem
The token `=` is overloaded across four unrelated roles, and three of them collide on the most token-frequent intent an LLM emits — equality. Concretely: (1) ASSIGNMENT/payload — `owner = nil`, `name = input.name` (examples/full-capsule/full-capsule.lzi:388-393; grammar `assignment = IDENT_LOWER "=" expr` docs/grammar.lzi.md:540, `creates_clause`/`emits_clause` :536-542); (2) FIELD DEFAULT — `tier: CustomerTier = free`, `health: @semantic.Percentage = 0` (full-capsule.lzi:54-55; grammar :309 `"=" default_value`); (3) ENUM STORAGE — `lead = 10` (full-capsule.lzi:30-33; grammar enum_variant :389; parser crates/lazuli_syntax/src/parser/lzi/enums.rs:60); (4) PREDICATE EQUALITY — `self.owner = nil`, `self.status = archived` (full-capsule.lzi:263,249-270). The closed predicate grammar admits ONLY single `=` for equality (docs/grammar.lzi.md:1110 `comparison = ref ( "=" | "!=" | "has" ) value`; filter_op :801), so an LLM’s reflexive `==` (its dominant trained equality token from Go/Python/JS/Rust) is a hard parse error at every predicate site. The two analyzer operator tables that lower verbatim predicate text confirm the single-`=` mapping: crates/lazuli_analyzer/src/agent.rs:342 `("=", ir::CompareOp::Eq)` in `parse_closed_predicate` (drives rule `tests denies/allows when`, conditional policy atoms lib.rs:198, `unique ... when` resource.rs:299-302, `invariant when` feature_meta.rs:84) and crates/lazuli_analyzer/src/query.rs:219 `("=", ir::CompareOp::Eq)` in `parse_query_filter_line` (drives `filters`). Two more comparison-context `=` parsers exist: the `.lzx` route-guard `requires <feature>.lookup_my.<field> = <literal>` predicate (crates/lazuli_syntax/src/parser/lzx/app/view_guard.rs:494-500) and the webhook emit `when payload.status = "approved"` predicate (crates/lazuli_analyzer/src/workflow.rs:99, whose own comment at :96-98 already anticipates `== if a future surface accepts it`). The IR is already ahead of the surface: `CompareOp::Eq` is documented as `/// ==` and `Ne` as `/// !=` (crates/lazuli_ir/src/nodes/query.rs:411-414). The drift hazard the CLAUDE.md attach_ctx cautionary tale warns about is LIVE: the static tmLanguage `operators` block ALREADY highlights `==` (editors/vscode/syntaxes/lazuli.tmLanguage.json:2862 `"match": "==|!=|<=|>=|<|>|="`) while the parser rejects it — highlighted-but-unparseable, the exact inversion that broke pilots before. Net effect: peakedness is destroyed (two spellings for equality, only one accepted) and every LLM authoring attempt that reflexively types `==` in a predicate costs a full doctor/compile round-trip to discover the surface diverges from every mainstream language it was trained on.

## End state
`==` is THE equality operator in the closed predicate language; bare `=` in any comparison context is a hard parse/analyzer error (`E-PREDICATE-EQ-RETIRED`) with a fix-it suggesting `==`. `=` retains exactly its three non-comparison roles — assignment/payload binding (`name = input.name`), field default (`tier = free`), enum storage (`lead = 10`) — plus the two lifecycle STATE-BINDING forms that are NOT boolean comparisons and stay out of scope by design (`requires_lifecycle <Resource> = <state>` view_guard.rs:655; `only_when lifecycle <R> = <state>`; lowered by lifecycle_gate_helpers/parse.rs:54 to a state binding, never to `CompareOp::Eq`). The four comparison-context parsers all switch their `Eq` token from `"="` to `"=="`: `parse_closed_predicate` (agent.rs), `parse_query_filter_line` (query.rs), the `requires ... = <literal>` guard (view_guard.rs), and `parse_emit_predicate_kind` (workflow.rs). `!=` (already `==`-adjacent in spelling) and `has` are unchanged. Grammar `comparison`/`filter_op`/`scope_predicate` productions read `"==" | "!=" | "has"`. The static tmLanguage operators block is corrected so `==`/`!=` are the canonical comparison highlights and a bare `=` inside an expression context resolves to `keyword.operator.assignment`, not `comparison`. LSP hover for `==` describes equality; typing single `=` in a predicate surfaces a file-local diagnostic with a code-action that rewrites to `==`. A doctor rule `PREDICATE-EQ-OPERATOR-001` (iron-hand) rejects the retired single-`=`-in-predicate form across `.lzi`/`.lzx`. examples/full-capsule rewritten so every predicate `=` becomes `==` (rules tests, filters, command/transition tests, the `requires`/emit guards) while assignment/default/enum-storage `=` are untouched; `lazuli inspect examples/full-capsule` produces byte-identical IR before/after the migration (proving the change is surface-only). A `lazuli upgrade` recipe mechanically rewrites predicate-context `=`→`==` with an input/output smoke fixture gated by the inspect-IR-equality check. The scaffold (`lazurite/templates/default`, whose only `.lzi` is registry.lzi with zero predicate sites) is unaffected and its doctor smoke stays green by construction.

## Justification (token / entropy)
"Optimizes EXPECTED TOKENS TO CORRECT OUTPUT = tokens-per-attempt × attempts, dominating on the ATTEMPTS axis via peakedness. Today equality has two surface spellings but only one is accepted: the model’s overwhelmingly trained reflex `==` (the equality token in Go, Python, JS, TS, Rust, Java, C — the entire pretraining corpus) is a HARD parse error in every Lazuli predicate, while the accepted form `=` collides at-a-point with assignment/default/enum-storage. Every predicate an LLM drafts therefore carries a high prior of an `==` miss that costs a full doctor/compile round-trip to discover the surface diverges from all mainstream languages — pure wasted attempts. Making `==` THE equality operator collapses output entropy to one canonical form that matches the trained reflex, so first-attempt predicates parse; bare `=` becoming a hard error with a one-token fix-it (`=`→`==`) means even a regression is corrected in a single deterministic edit rather than a re-derivation. Tokens-per-attempt is neutral-to-favorable: `==` and `=` are both single cl100k/o200k tokens, and disambiguating equality from assignment removes the cognitive/contextual load of inferring which role a `=` plays from surrounding grammar — the operator now carries its own meaning, which is exactly the tokenizer-cheap-surface principle (a self-describing English/symbol token beating context-dependent polysemy). The change also kills a LIVE drift hazard (tmLanguage already highlights `==` though the parser rejects it — the attach_ctx inversion) and aligns the surface with the IR, which already documents Eq as `==`. Net: strictly fewer attempts, equal-or-fewer tokens per attempt, lower expected tokens to correct output."
