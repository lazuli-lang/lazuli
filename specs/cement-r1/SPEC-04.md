# SPEC-04 — @ off types: @semantic.X and @cap.X become bare PascalCase reserved type names

**Breaking:** True | **Est. commits:** 9 | **Depends on:** SPEC-01 | **Parallel with:** SPEC-02

## Problem
Lazuli's scalar types are bare PascalCase (`Text`, `Integer`, `Decimal`) — resolved by the single type lifter `type_ref_from_syntax` at crates/lazuli_analyzer/src/types.rs:160-178 — but the CLOSED-CATALOG semantic and capability types still carry a `@`-sigil: `@semantic.Email`, `@cap.Encrypted(key:@key.tenant)` (canonical fixture examples/full-capsule/full-capsule.lzi:52,54,58). Both spellings already coexist for two of them: the lifter maps bare `Money` (types.rs:172) and bare `Email` (types.rs:178) to the SAME IR variants as `@semantic.Money`/`@semantic.Email` (types.rs:152-156, 140), proving the migration is half-done and the sigil is redundant for the closed core. The sigil makes `@` straddle four unrelated semantic kinds — type (`@semantic.Email`), classification (`@pii.contact`), authz-atom (`@scope.authenticated`), named-ref (`@fn.foo`) — which design-decisions.md:131-160 defends as 'axis per namespace' but which costs tokens at every type site for zero disambiguation benefit (a type position is unambiguous). Token cost: under cl100k/o200k `@semantic.Email` is ~4 tokens (`@`,`semantic`,`.`,`Email`) vs bare `Email` = 1 token; `@cap.Encrypted` ~4 tokens vs `Encrypted` = 1. ENTROPY cost: two valid spellings per closed-core type (bare `Money` AND `@semantic.Money` both parse, types.rs:152/172) is a non-peaked surface — an LLM samples either form, so cold-authored code drifts and round-trips inconsistently. The closed catalog is exactly Email/Phone/Url/Uuid/Currency/GeoPoint/Money/HexColor/Percentage (BuiltinType, crates/lazuli_ir/src/nodes/resource/type_ref.rs:73-116; mirrored as BUILT_IN_SEMANTIC at crates/lazuli_doctor_run/src/doctor/aggregators/lazurite_manifest/plugins_semantic.rs:135-145) plus capabilities File/PII/Hashed/Encrypted/E2ee/Token (CapabilityRef, crates/lazuli_ir/src/nodes/capability.rs:54-73). These are collision-safe-by-reservation exactly like `Text` already is (the highlighter at crates/lazuli_syntax/src/parser/highlight.rs:258-264 already classifies every bare IDENT_UPPER as SemanticToken::Type 'safe anywhere'). The sigil buys nothing in type position and taxes every field declaration. Critically, the `@semantic` namespace ALSO carries OPEN plugin-declared aliases (`@semantic.BrazilianCPF` → SemanticPluginType, type_ref.rs:117-157; resolved at plugins_semantic.rs:155-187 SEMANTIC-PLUGIN-001) which are NOT a closed catalog and CANNOT become bare reserved names without colliding with user resource names — so the cut is asymmetric and must be designed carefully.

## End state
In type position, `@` NEVER appears for the closed core. The nine closed-core semantic scalars and six capability types become BARE PascalCase reserved names in the closed type catalog, collision-safe exactly like `Text`: `Email`, `Phone`, `Url`, `Uuid`, `Currency`, `GeoPoint`, `Money`, `HexColor`, `Percentage`, `File`, `Encrypted(key:Key.tenant)`, `Hashed(algorithm:argon2id)`, `E2ee(key:Key.tenant)`, `Token(ttl:15m,single_use:true,store:hashed)`, `Secret`, `PII(class:contact)`. Capability ARGS keep their `key:value` form but the `@key.` ref inside `Encrypted`/`E2ee` becomes the bare `Key.tenant` (or stays `@key.tenant` ONLY if SPEC-03 keeps `@key` as a classification sigil — see coordination). `@semantic.*` and `@cap.*` are DELETED from the type grammar: the parser/lifter no longer recognizes them in type position and the `@cap` namespace is removed from the closed namespace catalog entirely (vocab.rs:215-244). The `@semantic` namespace SURVIVES but is RE-SCOPED to ONLY open plugin-declared aliases (`@semantic.BrazilianCPF`) — a plugin scalar keeps its sigil precisely because it is declared-custom (open), not closed-core, mirroring the 'closed core + declared-custom flexibility' doctrine (commit 098c50e2). This makes the sigil MEANINGFUL: `@semantic.X` now signals 'this came from a plugin, not the core' — a 1:1 visible distinction instead of a redundant decoration. The one canonical form per intent: bare name ⇒ core type; `@semantic.<Alias>` ⇒ plugin type. The IR is UNCHANGED — `BuiltinType`/`CapabilityRef` variants stay byte-identical; this is a pure surface (parser-text + LSP + tmLanguage + docs + fixtures + codegen-fallback-strings) sweep. The `contains @semantic.Email` agent-eval predicate (crates/lazuli_syntax/src/parser/lzi/agent/evals.rs:275-283; design-decisions.md:331) migrates to `contains Email`. `lazuli inspect` on every fixture and a fresh scaffold produces byte-identical IR pre/post migration (verified by the upgrade recipe's existing IR-equivalence smoke at crates/lazuli_cli/src/upgrade.rs:143-191).

## Doctor rules
- `VOCAB-TYPE-SIGIL-RETIRED-001` (error) — Rejects retired `@semantic.<CoreType>` and `@cap.<Type>` in type position (field/route/param/return/extension-type sites), suggesting the bare PascalCase reserved name (`@semantic.Email`→`Email`, `@cap.Encrypted(key:Key.tenant)`→`Encrypted(key:Key.tenant)`). Iron-hand (Error) severity since FULL BREAKING is approved and the migration recipe auto-rewrites; closed-core only — `@semantic.<PluginAlias>` is explicitly allowed (cross-checked against the BUILT_IN_SEMANTIC catalog so plugin aliases pass through). Module header carries severity + trigger cue 'fires when a field type names @semantic.<core> or @cap.<x>'.
- `VOCAB-TYPE-RESERVED-COLLISION-001` (error) — Rejects a user `resource`/`record`/`enum` declared with a name that collides with a reserved bare type name (Email/Phone/Url/Uuid/Currency/GeoPoint/Money/HexColor/Percentage/File/Encrypted/Hashed/E2ee/Token/Secret/PII) — the collision-safety guarantee that makes bare reservation sound, mirroring how `Text`/`Integer` are already protected. Iron-hand (Error). Extends the existing reserved-name policy at crates/lazuli_analyzer/src/design.rs:194 / scalar_fixtures/mod.rs:355.
- `VOCAB-SEMANTIC-PLUGIN-SIGIL-001` (warn) — Affirmative rule (Warn): a `@semantic.<Name>` whose `<Name>` IS in the closed BUILT_IN_SEMANTIC catalog is a retired core spelling (covered by 001); a `@semantic.<Name>` NOT in the catalog and NOT resolving to a declared plugin is SEMANTIC-PLUGIN-001 (preexisting). This rule documents/guards the surviving meaning of the sigil so audits don't propose deleting the `@semantic` namespace wholesale. Warn severity; module header trigger cue 'warns when @semantic carries a name outside both the core catalog and declared plugins'.
