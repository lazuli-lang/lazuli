# SPEC-11 — Docs 3-layer reorg (normative/teaching/rationale) + de-dictatorialize + generated closed-catalog includes + CLAUDE.md/AGENTS.md reconciliation

**Breaking:** True | **Est. commits:** 9 | **Depends on:** SPEC-01 | **Parallel with:** none

## Problem
The real language spec is scattered and self-contradicting across three drifted surfaces, and the framework's own grammar admits its tooling rejects. Concrete, cited drift:

1. PERMISSIVE GRAMMAR / NO SINGLE NORMATIVE LAYER. `docs/grammar.lzi.md:1137` literally states "The grammar admits constructs that doctor or `lazuli check` reject" and `:8-12` says "Where this grammar disagrees with prose docs, the prose wins" — i.e. the EBNF is decorative, and the *actual* spec is 718 LOC of imperative prose in `docs/invariants.md` + 3148 LOC of `docs/canonical-semantics.md` + doctor lints. There is no authoritative, generated, single-source normative layer; the closed catalogs (the part most likely to drift) are hand-copied into prose.

2. THREE NAMESPACE LISTS, ALL DIFFERENT. The closed reference-namespace catalog exists in code at `crates/lazuli_lsp/src/diagnostics/vocab.rs:215-267` with 22 entries (role, scope, actor, policy, semantic, cap, pii, key, fn, hook, validator, adapter, client, query_modifier, anchor, llm, tool, trace, translation, feature, command, file, audience) — duplicated by hand in a second `matches!` block at `crates/lazuli_doctor_run/src/doctor/refs.rs:209-231`. But `docs/design-decisions.md:144-149` documents only 17 (omits trace, translation, feature, command, file, audience), and `docs/grammar.lzi.md:33-36` documents only 17 (the same omission). An LLM cold-reading the docs cannot author `@trace.*`, `@translation.*`, `@audience.*` even though the parser accepts them — and the namespace list is the single most-cited closed catalog in the language.

3. @semantic.Slug GHOST + COUNT DRIFT. `docs/grammar.lzi.md:279` lists `Slug` among the "established scalars (`Email`, `Slug`, `Url`, `Money`, `Phone`, ...)" of the `@semantic.*` catalog. But the canonical catalog in `crates/lazuli_ir/src/nodes/resource/type_ref.rs:72-116` has NO `SemanticSlug`; `@slug` is a field-marker decorator (`crates/lazuli_keywords/src/registry.rs:3192` `decorator("@slug", ...)`, grammar.lzi.md:296). Separately the catalog count drifts three ways: code has 9 members (Email, Money, Phone, Url, Uuid, Currency, GeoPoint, HexColor, Percentage — type_ref.rs:72-116), `docs/style-guide.md:264` lists 7 (no HexColor/Percentage), `docs/grammar.lzi.md:279` lists a 5-item sample with a wrong member. The single most type-relevant closed catalog disagrees across three docs and code.

4. DICTATORIAL TONE IN THE NORMATIVE LAYER. The descriptive spec is written like a constitution: 16 NEVER/MUST/Inviolable/never/always tokens in `docs/invariants.md` (e.g. :281 "MUST be marked", :613 "MUST author", :675/:682/:687/:699/:713 "MUST NOT"/"MUST"), 19 in `docs/canonical-semantics.md`. Firm contributor-discipline tone belongs in CLAUDE.md (contributor-facing); a normative reference an LLM reads to author code should be calm and descriptive ("X declares Y") so the model spends tokens on the construct, not on parsing prohibitions.

5. CLAUDE.md/AGENTS.md STALE + MISSING THE GENERATION RULE. CLAUDE.md (and its byte-identical mirror AGENTS.md) documents the keyword-parity discipline (CLAUDE.md:174-189) but its "Curated grammar + teaching docs" row (CLAUDE.md:183) treats grammar.*.md as the catalog home, and the namespace policy section (CLAUDE.md:41-49) never states the rule that the closed *value* catalogs (namespaces, semantic scalars, scalar types, enum values) are generated and never hand-edited — which is exactly the rule whose absence produced drifts (2) and (3).

The registry IS a pure projector today (`tools/xtask/src/keyword_reference.rs:36-80`, `keyword_surface_parity.rs:1-50`) but it only projects keyword *literals*; the `decorator(...)` rows (`registry.rs:514-526`, `:3177-3222`) carry the namespace token but NOT the closed member catalog, so the members live un-generated in `type_ref.rs` and the two `matches!` allowlists. This spec closes the loop: model the catalogs in the registry, generate the normative catalog docs from it, de-dictatorialize, split the three doc layers, and reconcile CLAUDE.md/AGENTS.md as the LAST spec describing the final state.

## Justification (token / entropy)
SPEC-11 directly minimizes EXPECTED TOKENS TO CORRECT OUTPUT = tokens-per-attempt x attempts on both factors.

PEAKEDNESS (fewer attempts). Today an LLM authoring `@trace.*` or `@audience.*` reads design-decisions.md:144-149 / grammar.lzi.md:33-36, sees only 17 namespaces, and either (a) avoids a valid construct or (b) invents a wrong one — then the parser rejects and it retries. Worse, it may copy the ghost `@semantic.Slug` (grammar.lzi.md:279) which the analyzer rejects (type_ref.rs has no SemanticSlug), guaranteeing a failed attempt + a correction round. Drift across three catalog copies means the model has THREE conflicting priors for one closed set — maximal output entropy exactly where the language is supposed to be closed and peaked. Generating the catalogs from one registry source (the SPEC-01 mechanism extended here) collapses the three copies to one canonical rendering: one prior, one form, near-zero retry on catalog membership. The doctor rules (DOCS-CATALOG-DRIFT-001 / NAMESPACE-SINGLE-SOURCE-001) make re-divergence impossible by construction, so peakedness is durable, not a one-time cleanup.

TOKENS-PER-ATTEMPT (cheaper attempts). De-dictatorializing the normative layer removes ~35 SHOUTED NEVER/MUST/Inviolable banner tokens (16 in invariants.md + 19 in canonical-semantics.md) that an authoring model must read and parse as constraints rather than content. A calm descriptive reference ('X declares Y') is fewer tokens to ingest per read and lowers the cognitive/parsing overhead per attempt — the model spends its budget on the construct, not on decoding prohibitions.
